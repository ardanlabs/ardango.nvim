1. Introduction                                          *ardango-introduction*
                                                                     *ardango*

ardango.nvim exposes utility functions to enhance coding Go in Neovim:
running/building via the go toolchain, organizing imports, editing struct
tags, showing hover info in the statusline, and driving a Delve debug
session (see |ardango-debug|).

Dependencies ~
    - nvim-treesitter (with the Go parser installed)
    - nvim-lspconfig
    - nui.nvim
    - telescope.nvim (optional - enables fuzzy pickers for tag prompts and
      for browsing test/build failures; falls back to plain vim.ui.input/
      the quickfix list if it isn't installed)
    - gofmt (optional, ships with the Go toolchain - used to re-align
      struct columns after a tag edit; skipped silently if not on PATH)

2. Setup                                                          *ardango-setup*

Requiring the plugin is enough to use its commands with their defaults:
>lua
    local ardango = require("ardango")
<
Call |ardango.setup()| to override the results popup or the tag-options
list - see |ardango-configuration|. It's optional; everything works with
its defaults if you skip it.

Example keymaps: >lua
    local ardango = require("ardango")
    local opts = { noremap = true, silent = true }

    vim.keymap.set("n", "<leader>gt", ardango.RunCurrTest, opts)
    vim.keymap.set("n", "<leader>gf", ardango.RunFileTests, opts)
    vim.keymap.set("n", "<leader>ga", ardango.RunPackageTests, opts)
    vim.keymap.set("n", "<leader>gb", ardango.RunCurrBenchmark, opts)
    vim.keymap.set("n", "<leader>gp", ardango.BuildCurrPackage, opts)
    vim.keymap.set("n", "<leader>gd", function() ardango.RunCurrTest({ dry_run = true }) end, opts)
    vim.keymap.set("n", "<leader>gc", ardango.CopyLastCmd, opts)
    vim.keymap.set("n", "<leader>gr", ardango.RunLastTest, opts)

    vim.keymap.set("n", "<leader>taf", ardango.AddTagToField, { buffer = 0 })
    vim.keymap.set("n", "<leader>tas", ardango.AddTagsToStruct, { buffer = 0 })
    vim.keymap.set("n", "<leader>trf", ardango.RemoveTagFromField, { buffer = 0 })
    vim.keymap.set("n", "<leader>trs", ardango.RemoveTagsFromStruct, { buffer = 0 })

    -- Visual-mode variants need <Esc> before the Lua call, so leaving
    -- Visual mode sets the '</'> marks before the function runs.
    vim.keymap.set("x", "<leader>tavf",
      "<Esc>:lua require('ardango').AddTagToVisualFields()<CR>", { buffer = 0 })
    vim.keymap.set("x", "<leader>trvf",
      "<Esc>:lua require('ardango').RemoveTagFromVisualFields()<CR>", { buffer = 0 })

    -- Debugging (Delve) - see |ardango-debug|.
    vim.keymap.set("n", "<leader>dt", ardango.DebugCurrTest, opts)
    vim.keymap.set("n", "<leader>dP", ardango.DebugPackage, opts)
    vim.keymap.set("n", "<leader>db", ardango.DebugBreakpoint, opts)
    vim.keymap.set("n", "<leader>dc", ardango.DebugContinue, opts)
    vim.keymap.set("n", "<leader>dn", ardango.DebugStepOver, opts)
    vim.keymap.set("n", "<leader>ds", ardango.DebugStepInto, opts)
    vim.keymap.set("n", "<leader>do", ardango.DebugStepOut, opts)
    vim.keymap.set("n", "<leader>de", ardango.DebugEval, opts)
    vim.keymap.set("x", "<leader>de",
      "<Esc>:lua require('ardango').DebugEvalVisual()<CR>", opts)
    vim.keymap.set("n", "<leader>dl", ardango.DebugLocals, opts)
    vim.keymap.set("n", "<leader>dS", ardango.DebugStack, opts)
    vim.keymap.set("n", "<leader>d[", ardango.DebugFrameUp, opts)
    vim.keymap.set("n", "<leader>d]", ardango.DebugFrameDown, opts)
    vim.keymap.set("n", "<leader>dg", ardango.DebugGoroutines, opts)
    vim.keymap.set("n", "<leader>dm", ardango.DebugBreakpoints, opts)
    vim.keymap.set("n", "<leader>dq", ardango.DebugStop, opts)

    -- Update imports on save.
    vim.api.nvim_create_autocmd("BufWritePre", {
      pattern = "*.go",
      callback = function() ardango.OrgBufImports(1000) end,
    })
<

3. Commands                                                    *ardango-commands*

All of these are Lua functions on the module returned by
require("ardango") - wire them up to keymaps/autocmds as shown in
|ardango-setup|, or reach them from the cmdline via :Ardango, see
|ardango-ex-command|.

ardango.RunCurrTest({opts})                                *ardango.RunCurrTest*
    Runs the test under the cursor and shows the results in a popup window
    by default. {opts} is an optional table:
      - quickfix  (boolean) show results in the quickfix list instead
      - telescope (boolean) show results via Telescope instead (implies
                    quickfix; falls back to the quickfix list if
                    telescope.nvim isn't installed)
      - verbose   (boolean) also list passing tests, one green line each
      - dry_run   (boolean) don't run anything - just notify the exact
                  go test/go build command that would run. Also works
                  on RunFileTests/RunPackageTests/RunCurrBenchmark/
                  BuildCurrPackage. Pair with |ardango.CopyLastCmd| to
                  get that command onto the clipboard.
    See |ardango-configuration| for the popup's own settings.

ardango.RunFileTests({opts})                              *ardango.RunFileTests*
    Runs every test declared in the current buffer. Same {opts} as
    |ardango.RunCurrTest|.

ardango.RunPackageTests({opts})                        *ardango.RunPackageTests*
    Runs every test in the current package (the whole directory, not just
    the current file). Same {opts} as |ardango.RunCurrTest|.

ardango.RunCurrBenchmark({opts})                      *ardango.RunCurrBenchmark*
    Runs the benchmark under the cursor (go test -bench '^Name$' -run
    '^$' -benchmem) and shows the ns/op and allocation stats in a popup
    by default. Same {opts} as |ardango.RunCurrTest|, except
    opts.verbose is a no-op - go test has no verbose flag for
    benchmarks.

ardango.BuildCurrPackage({opts})                      *ardango.BuildCurrPackage*
    Builds the package in the current directory. Same {opts} as
    |ardango.RunCurrTest|.

ardango.CopyLastCmd()                                        *ardango.CopyLastCmd*
    Copies the most recently computed go test/go build command (from
    any Run*/BuildCurrPackage call above - a dry run or a real one,
    either counts) onto the system clipboard (the "+" register), so it
    can be pasted into a terminal and run manually.

ardango.RunLastTest({opts})                                  *ardango.RunLastTest*
    Re-runs whatever Run*/BuildCurrPackage invocation was most recently
    computed (test, benchmark or build alike - whatever it was),
    without needing to reposition the cursor. {opts} is merged over
    (and overrides) the opts used last time - e.g. RunLastTest({
    quickfix = true }) reruns the same command but through the
    quickfix list this time. Always actually runs, even if the last
    invocation was itself an opts.dry_run preview - pass { dry_run =
    true } again to re-preview instead.

ardango.OrgBufImports({wait_ms})                        *ardango.OrgBufImports*
    Organizes/updates the imports of the current buffer via the attached
    LSP client's source.organizeImports code action, waiting up to
    {wait_ms} milliseconds for a response.

ardango.SignatureInStatusLine({wait_ms}, {opts})  *ardango.SignatureInStatusLine*
    Shows the signature/definition of the element under the cursor via
    LSP hover, waiting up to {wait_ms} milliseconds. {opts} is an
    optional table:
      - float (boolean) instead of a one-line vim.notify summary
              (close to the statusline), open a floating window with
              the full hover content, via the same
              vim.lsp.util.open_floating_preview vim.lsp.buf.hover()
              itself uses.

ardango.AddTagToField()                                  *ardango.AddTagToField*
    Adds a tag element to the struct field under the cursor (handles
    fields that already have tags/other elements). Prompts for the tag
    name via a fuzzy-searchable picker of common names (json, yaml, db,
    validate, xml - typing something that doesn't match uses what you
    typed), then a single combined prompt for the tag value and its
    common options: <Tab>-toggle any of the |ardango-configuration|
    tag_options (default omitempty/-/required; they stay selected
    as you type, even though typing filters the visible list), then type
    the value (empty defaults to the snake_cased field name) and confirm
    with <CR>. Picking - wins over everything else, since a bare -
    means "skip this field" per Go tag convention. Falls back to plain
    vim.ui.input prompts if telescope.nvim isn't installed. Every
    struct-tag command re-runs the buffer through gofmt afterward (if
    it's on PATH) so the struct's columns stay aligned - splicing raw
    text in doesn't otherwise re-align them.

ardango.AddTagsToStruct()                              *ardango.AddTagsToStruct*
    Same prompts as |ardango.AddTagToField|, but adds the tag element to
    every field inside the struct under the cursor.

ardango.RemoveTagFromField()                          *ardango.RemoveTagFromField*
    Removes a tag element from the field under the cursor. Same tag-name
    prompt as |ardango.AddTagToField| (no value/options step).

ardango.RemoveTagsFromStruct()                      *ardango.RemoveTagsFromStruct*
    Removes a tag element from every field inside the struct under the
    cursor. Same prompt as |ardango.RemoveTagFromField|.

ardango.AddTagToVisualFields()                    *ardango.AddTagToVisualFields*
    Same prompts as |ardango.AddTagToField|, scoped to every field
    declared inside the last Visual-mode selection instead of every field
    in the struct or just the one under the cursor. Meant to be called
    from a Visual-mode keymap that exits Visual mode first (see the
    example in |ardango-setup|) so the '</'> marks are set before it
    runs.

ardango.RemoveTagFromVisualFields()          *ardango.RemoveTagFromVisualFields*
    Same as |ardango.RemoveTagFromField|, scoped to the last Visual-mode
    selection.

4. Ex command                                                *ardango-ex-command*

Every command in |ardango-commands| is also reachable from the cmdline
via: >vim
    :Ardango {Command} [flag...]
<
with tab completion for both {Command} and any boolean flags it accepts
(quickfix, telescope, verbose, dry_run, float) - handy if you don't want
to set up keymaps for everything. OrgBufImports/SignatureInStatusLine
take a milliseconds number instead of/alongside flags (defaults to 1000
if omitted). Examples: >vim
    :Ardango RunCurrTest
    :Ardango RunCurrTest quickfix verbose
    :Ardango RunCurrTest dry_run
    :Ardango RunLastTest
    :Ardango AddTagToField
    :Ardango SignatureInStatusLine 500 float
<

5. Debugging (Delve)                                             *ardango-debug*

Drive a Delve debug session on the current buffer's package without
leaving Neovim. One session runs at a time. A breakpoint sign (default
"●") marks lines you've toggled; the current stop location gets a "▶"
sign and the cursor jumps there.

Requirements ~
    - dlv (Delve) on PATH - https://github.com/go-delve/delve
    - the Go toolchain (`go`) - a small helper (cmd/ardango-dbg) is built
      automatically into stdpath("cache")/ardango/ on the first Debug*
      command, and rebuilt when it goes stale. dev/setup.sh pre-builds it.

Starting a session ~

ardango.DebugCurrTest()                                  *ardango.DebugCurrTest*
    Builds and debugs the Test* function under the cursor (dlv test) and
    stops on its first line (a one-shot entry breakpoint, cleared once
    hit). Drive it from there with the stepping commands below.

ardango.DebugCurrBenchmark()                        *ardango.DebugCurrBenchmark*
    Same for the Benchmark* function under the cursor
    (dlv test -- -test.run ^$ -test.bench ^Name$ -test.benchmem).

ardango.DebugPackage()                                    *ardango.DebugPackage*
    Debugs the current buffer's package as a program (dlv debug). Unlike
    the two above it does not auto-stop - set a breakpoint, then
    |ardango.DebugContinue|.

ardango.DebugStop()                                          *ardango.DebugStop*
    Ends the session: detaches and kills the debuggee, clears the signs.
    The session is also torn down automatically when the program exits
    and when Neovim quits.

Stepping (only while the target is halted) ~

ardango.DebugContinue()                                  *ardango.DebugContinue*
    Run until the next breakpoint or program exit.

ardango.DebugStepOver()                                  *ardango.DebugStepOver*
    Step over the current line. (Alias: ardango.DebugNext.)

ardango.DebugStepInto()                                  *ardango.DebugStepInto*
    Step into a call on the current line. (Alias: ardango.DebugStep.)

ardango.DebugStepOut()                                    *ardango.DebugStepOut*
    Run until the current function returns.

Breakpoints ~

ardango.DebugBreakpoint({cond})                        *ardango.DebugBreakpoint*
    Toggle a breakpoint on the current line. Works with no session
    running (breakpoints persist across sessions and are re-applied on
    the next start, and their signs come back when a file is reopened);
    toggling one while the target is running takes effect at the next
    stop. With {cond} - a Go boolean expression, e.g.
    ":ArdangoDebug break i > 5" - sets (or re-sets) a conditional
    breakpoint that only stops when the condition holds.

ardango.DebugBreakpoints({opts})                      *ardango.DebugBreakpoints*
    List every breakpoint (file:line + the source line) in a popup:
    <CR> jumps to it, dd deletes the one under the cursor, D clears all.
    opts.telescope (or :ArdangoDebug breaks telescope) opens a
    Telescope picker with a source preview instead - <C-d> deletes;
    falls back to the popup if telescope.nvim isn't installed.

ardango.DebugBreakpointClearAll()              *ardango.DebugBreakpointClearAll*
    Remove every breakpoint.

Status indicator ~

ardango.debug_status()                                  *ardango.debug_status*
    Returns a compact one-line status string for a statusline / winbar /
    lualine component - "" when there's no session, otherwise e.g.
    "[debug: testdata.Greet sample.go:13 g6 #2/5]" (function, short
    file:line, goroutine, and the frame number only when you've navigated
    off frame 0), or "[debug: starting]" / "[debug: running]" /
    "[debug: building helper]" during setup and a continue. >lua
        vim.o.statusline = "%f %{v:lua.require('ardango').debug_status()} %="
        -- or a window bar:
        vim.wo.winbar = "%{v:lua.require('ardango').debug_status()}"
        -- or a lualine section:
        { function() return require('ardango').debug_status() end }
<
    Every state change nudges |:redrawstatus| and fires a
    "User ArdangoDebug" autocmd for custom refresh hooks. :Ardango
    DebugStatus echoes the string as a notification.

Inspecting state (only while the target is halted) ~

ardango.DebugEval({expr})                                    *ardango.DebugEval*
    Evaluate {expr} in the selected frame and show the value in a floating
    window, like |vim.lsp.buf.hover()|. With no {expr}, evaluates the
    <cexpr> under the cursor (`p`, `p.Name`, `xs[i]`, ...).

ardango.DebugEvalVisual()                              *ardango.DebugEvalVisual*
    Like |ardango.DebugEval|, but evaluates the last Visual selection
    (e.g. `p.Items[i].Name`). Meant for an x-mode keymap that leaves
    Visual mode first: >lua
        vim.keymap.set("x", "<leader>de",
          "<Esc>:lua require('ardango').DebugEvalVisual()<CR>")
<

ardango.DebugLocals()                                      *ardango.DebugLocals*
    List the selected frame's arguments and local variables in a popup
    ("-- args --" / "-- locals --" / "-- returns --"), one line each,
    values capped for the list view - use |ardango.DebugEval| for the
    full value.

ardango.DebugStack()                                        *ardango.DebugStack*
    Show the current goroutine's call stack in a popup. <CR> on a frame
    line selects it (cursor + sign move there and DebugLocals/DebugEval
    then operate in it - same as |ardango.DebugFrame|); the selected
    frame is marked "←".

Stack frames (only while the target is halted) ~

ardango.DebugFrameUp()                                    *ardango.DebugFrameUp*
ardango.DebugFrameDown()                                *ardango.DebugFrameDown*
    Move the selected frame one step toward the caller / callee. The
    cursor jumps to that frame's source and the position sign changes to
    "▷" for any frame above the innermost ("▶"). |ardango.DebugLocals| and
    |ardango.DebugEval| then evaluate in the selected frame.

ardango.DebugFrame({n})                                      *ardango.DebugFrame*
    Select frame {n} directly (0 = innermost).

The selected frame resets to 0 on the next
Continue/StepOver/StepInto/StepOut.

Goroutines (only while the target is halted) ~

ardango.DebugGoroutines({opts})                        *ardango.DebugGoroutines*
    List goroutines in a popup - user-code location, status, function -
    with the current one marked "←". <CR> on a line switches to that
    goroutine. Pure-runtime goroutines (parked in runtime.*, no user
    frame) are collapsed behind a "[+N runtime]" line; press `a`, or pass
    opts.all / ":ArdangoDebug goroutines all", to show them.

ardango.DebugGoroutine({id})                            *ardango.DebugGoroutine*
    Make goroutine {id} (from |ardango.DebugGoroutines|) the selected
    one and land on its first user frame. |ardango.DebugLocals| /
    |ardango.DebugEval| / |ardango.DebugStack| then reflect it.

Ex command ~
                                                          *:ArdangoDebug*
Every command above is also reachable as :ArdangoDebug {sub} [args], with
tab completion. {sub} is one of: >
    test  bench  package        - start a session
    continue  over  into  out   - run control
    stop                        - end the session
    break [cond]                - toggle a breakpoint here (arg: condition)
    breaks [telescope]          - list breakpoints
    clearbreaks                 - remove every breakpoint
    eval [expr]                 - evaluate (arg: expression; default <cexpr>)
    locals  stack               - inspect the frame
    up  down  frame {n}         - move the selected stack frame
    goroutines [all]  goroutine {id}
    status                      - echo the current status
    menu                        - the picker (see below)
<
Examples: >
    :ArdangoDebug test
    :ArdangoDebug break i > 5
    :ArdangoDebug eval p.Name
    :ArdangoDebug frame 2
<
                                                        *ardango.DebugMenu*
:ArdangoDebug with no argument (or `menu`, or require("ardango").DebugMenu())
opens a picker of every debug command with a one-line description. With
telescope.nvim installed it's a Telescope picker (fuzzy find + narrow);
otherwise it's |vim.ui.select()| - which fuzzy-finds through
telescope-ui-select / dressing.nvim / snacks / fzf-lua if one is set up,
or is a plain numbered prompt. Commands that take an argument (eval,
break, frame, goroutine) prompt for it after selection.

6. Configuration                                          *ardango-configuration*

ardango.setup({opts})                                          *ardango.setup*
    Overrides plugin-wide config. Optional - everything works with its
    defaults if you never call this. >lua
        require("ardango").setup({
          popup = {
            border = "single",    -- default: "rounded"
            size = "80%",         -- default: "50%"
            relative = "editor",  -- default: "cursor"
            position = "50%",     -- default: 0
          },
          tag_options = { "omitempty", "-", "required", "unique", "index" },
          debug = {
            dlv_args = { "--build-flags=-tags=integration" },  -- default: {}
            env = { CGO_ENABLED = "0" },                       -- default: {}
          },
        })
<
    popup fields are passed straight through to nui.Popup (|nui.popup|),
    so any shape it accepts for size/position works here too. This is
    the results popup used by |ardango.RunCurrTest| and friends when
    opts.quickfix/opts.telescope aren't set.

    tag_options is the list offered (via <Tab>-toggle) in the tag
    value/options prompt used by |ardango.AddTagToField| and friends.
    Passing it *replaces* the default list entirely, rather than merging
    with it.

    debug.dlv_args is a list of extra flags inserted into the dlv test /
    dlv debug command line (before the -- test-args separator) by the
    Debug* commands - e.g. build tags. Also replaces, not merges.

    debug.env is a table of name=value strings merged over Neovim's
    environment for the child processes that compile Go - the dlv
    session and the helper's `go build`. Values must be strings. Mainly
    for NixOS, where cgo hardening breaks Delve's unoptimised build of
    the target ("_FORTIFY_SOURCE requires compiling with optimization"):
    set { CGO_ENABLED = "0" } if the target needs no cgo, otherwise
    { CGO_CFLAGS = "-O2" }.

7. Health                                                        *ardango-health*

Run :checkhealth ardango to verify the go binary and the Go treesitter
parser are available (both required), nui.nvim is installed (required
for the default results popup), and whether telescope.nvim, gofmt, dlv
(Delve), and the built debug helper are present (all optional).
